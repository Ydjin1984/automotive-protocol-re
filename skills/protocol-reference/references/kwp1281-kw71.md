# VAG: KWP1281, KW71 и TP2.0

## 0. Семейство VAG

KW71 (VAG 1551/1552, самый старый) → **KWP1281** (K-line, блоки с комплементами) → KWP2000 (K-line 10.4k, см. `kwp2000-iso14230.md`) → **TP2.0** (CAN, с ~2002). Типовые скорости K-line: KWP1281 — 9600 (практика) / до 10400 (определяется синхробайтом), KWP2000 — 10400. Утверждение «KWP1281 = 10400 по умолчанию» — расхождение источников: фактическую скорость задаёт ЭБУ синхробайтом 0x55.

## 1. KWP1281 (блоковый протокол)

### 1.1 Инициализация
- 5 бод, **адрес 0x01** (не 0x33!), фрейминг 7O1 (7 данных + odd parity), 200 мс/бит.
- Ответ ЭБУ (handshake): **`55 01 8A 75`** — `0x55` синхро (задаёт скорость), keyword `01 8A`, `0x75 = 0xFF−0x8A`; тестер подтверждает инверсией.
- Для сравнения, KWP2000-ЭБУ ответил бы `55 6B 8F`-стилем (ключи 0x8F xx).

### 1.2 Блок (обрати внимание: чексуммы НЕТ)
Каждый байт передаётся вместе со своим **комплементом `0xFF − b`**:

```
length, ~length, counter, ~counter, title, ~title, data…, ~data…, 0x03
```
- `length` — число байт, следующих за ним **включая его самого**, но **без** завершающего 0x03.
- `counter` — инкремент на каждый блок, заворот 0xFF→0x00, сброс в 0 при ошибке.
- `0x03` — конец блока, **единственный байт без комплемента**.

Титулы блоков: `0x05` clear errors, `0x06` end output, `0x07` get errors, `0x09` ACK, `0x29` group reading, `0xE7` group reading response, `0xF6` ASCII data, `0xFC` get-errors response.

Примеры (эталонные из публичных реализаций):
- ACK-блок: `03 FC 02 FD 09 F6 03` → разбор: `03` length; `FC` его комплемент (0xFF−0x03); `02` counter; `FD` комплемент (0xFF−0x02); `09` title=ACK; `F6` комплемент (0xFF−0x09); `03` конец блока.
- Запрос группового чтения: `04 FB <c> <~c> 29 D6 <group> 03`.

### 1.3 Тайминги
- Реализация-эталон вставляет **~5 мс паузу перед каждым байтом** к ЭБУ; ожидание комплемента — ~500 мс, иначе разрыв связи.
- ЭБУ ждёт эхо и игнорирует его (K-line полудуплекс).

### 1.4 Отличия от KWP2000
Другой handshake, побайтовый комплемент вместо аддитивной CS, блоковая структура с титулами, только 5-baud init.

## 2. KW71 (кратко)

Более старый протокол эпохи VAG 1551/1552: 5-baud init, L-line для адресации, K-line для данных. Точные байты handshake по надёжным публичным источникам — **не подтверждено**; при работе с таким ЭБУ снимай лог и разбирай по `log-analysis`.

## 3. TP2.0 (VAG, CAN)

- High-speed CAN **500 кбит/с, 11-битные ID**.
- **Установка канала**: тестер → ID `0x200`; ECU отвечает на `0x200 + логический адрес` (двигатель 0x01 → 0x201). В setup задаются RX/TX-ID (пример: ECU слушает 0x300, передаёт 0x7A8).
- Опкоды: setup `0xC0` / положительный `0xD0` / отрицательные `0xD6..0xD8` (7 байт, поле App = `0x01` для KWP2000); параметры канала `0xA0`/`0xA1` (6 байт); тест `0xA3`; break `0xA4`; disconnect `0xA8`.
- Данные: 1-й ниббл первого байта: `0` ждать ACK, есть продолжение; `1` ждать ACK, последний; `2` без ACK, продолжение; `3` без ACK, последний. 2-й ниббл — sequence. ACK: `0xB*` (готов) / `0x9*` (не готов).
- Пример: пакет `12 00 02 1A 9B` (op=1, seq=2, длина 0x0002 BE, payload `1A 9B` = ReadECUIdentification) → ACK `B3`. Broadcast `0x23`/`0x24` шлётся 5 раз без ACK.
- KWP2000-запросы переносятся внутри: `10 89` → `50 89`.

## 4. Практика

- Инструменты: VCDS (сам делает init), ELM327 (для KWP1281 не годится — другой протокол!), Arduino/ESP-логгер (KLineKWP1281Lib), логический анализатор.
- При захвате KWP1281 важны паузы между байтами — логируй с точным таймстампом и не «склеивай» поток при парсинге (framing по паузам, см. `log-analysis`).
- TP2.0 ловится любым CAN-логгером (candump/Asc/…) — фильтруй по ID 0x200/0x2xx-семейству.
