# SAE J2534 Pass-Thru — API программирования и «моста» к OEM-ПО

J2534 — стандарт «сквозного» API: диагностическое/программирующее ПО (OEM-клиент) через единый DLL-интерфейс говорит с любым J2534-адаптером. В реверс-задачах J2534 ценен двумя сторонами: (а) как готовое железо, которое умеет то, чего не умеет FTDI (аппаратный 5-baud init, программирующее напряжение), (б) как **слой для логгера** — прокси-DLL между ПО и адаптером.

## 1. API-поверхность (J2534-1)

```c
PassThruOpen(void* pName, unsigned long* pDeviceID)
PassThruClose(unsigned long DeviceID)
PassThruConnect(DeviceID, ProtocolID, Flags, Baudrate, unsigned long* pChannelID)
PassThruDisconnect(ChannelID)
PassThruReadMsgs(ChannelID, PASSTHRU_MSG* pMsg, unsigned long* pNumMsgs, unsigned long Timeout)
PassThruWriteMsgs(ChannelID, PASSTHRU_MSG* pMsg, unsigned long* pNumMsgs, unsigned long Timeout)
PassThruStartPeriodicMsg(ChannelID, const PASSTHRU_MSG*, unsigned long* pMsgID, unsigned long TimeInterval)
PassThruStopPeriodicMsg(ChannelID, MsgID)
PassThruStartMsgFilter(ChannelID, FilterType, pMask, pPattern, pFlowControl, unsigned long* pFilterID)
PassThruStopMsgFilter(ChannelID, FilterID)
PassThruSetProgrammingVoltage(DeviceID, PinNumber, Voltage)   // напр. 5..20 В на pin 13/15 (flash)
PassThruReadVersion(DeviceID, pApiVersion, pDllVersion, pFirmwareVersion)  // pApiVersion = "04.04"
PassThruGetLastError(char* pErrorDescription)
PassThruIoctl(ChannelID, IoctlID, const void* pInput, void* pOutput)
```

`PASSTHRU_MSG` (packed): `ProtocolID, RxStatus, TxFlags, Timestamp(µs, 32 бита → wrap ~71.6 мин), DataSize, ExtraDataIndex, Data[4128]`.

ProtocolID: `1` J1850VPW, `2` J1850PWM, `3` ISO9141, `4` ISO14230, `5` CAN, `6` ISO15765, `7` SCI_A_ENGINE, `8` SCI_A_TRANS, `9` SCI_B_ENGINE, `10` SCI_B_TRANS.

Ключевые IoctlID: `GET_CONFIG=1`, `SET_CONFIG=2`, `READ_VBATT=3`, **`FIVE_BAUD_INIT=4`** (Input = SBYTE_ARRAY с адресом; Output = key bytes; поведение инверсии — через SET_CONFIG `FIVE_BAUD_MOD=0x22`), **`FAST_INIT=5`**, `CLEAR_TX_BUFFER=7`, `CLEAR_RX_BUFFER=8`, `CLEAR_PERIODIC_MSGS=9`, `CLEAR_MSG_FILTERS=10`, `ADD/DELETE_TO_FUNCT_MSG_LOOKUP_TABLE=12/13`.

`SET_CONFIG` параметры (SELECT): DATA_RATE=0x01, NODE_ADDRESS=0x04, NETWORK_LINE=0x05, P1..P4_MIN/MAX=0x06..0x0D, W1..W5=0x0E..0x12, TIDLE=0x13, TINIL=0x14, TWUP=0x15, PARITY=0x16, BIT_SAMPLE_POINT=0x17, SYNC_JUMP_WIDTH=0x18, W0=0x19, T1_MAX..T5_MAX=0x1A..1E, ISO15765_BS=0x1F, ISO15765_STMIN=0x20, DATA_BITS=0x21, FIVE_BAUD_MOD=0x22, BS_TX=0x23, STMIN_TX=0x24, ISO15765_WFT_MAX=0x25, CAN_MIXED_FORMAT=0x8000.

## 2. Практика использования как железа

- ISO 9141/14230 (K-line) на J2534: `PassThruConnect(ISO9141/ISO14230, flags, 10400)`; флаг `ISO9141_NO_CHECKSUM=0x200` (не проверять CS), `ISO9141_K_LINE_ONLY=0x1000` (без L-line). Для 5-baud init — `PassThruIoctl(FIVE_BAUD_INIT)`, для fast — `FAST_INIT`.
- Для программирования: `PassThruSetProgrammingVoltage(device, 13 или 15, 5..20 В)`.
- Поиск установленных устройств: реестр `HKLM\SOFTWARE\WOW6432Node\PassThruSupport.04.04\<Vendor>` → значения `Function Library` (путь к DLL), `Name`, `Vendor`, `Config Application`.
- Версии: J2534-1 `04.04` (2004; эталон тестов J1699-3), `05.00` (2022). J2534-2 — расширения (SW-CAN, GM UART, J1939, TP2.0, Fault-Tolerant CAN, CAN FD, Ethernet). Приложение может требовать **32-битную** DLL (большинство OEM-флешеров — 32-битные).

## 3. J2534 как логгер (прокси между ПО и адаптером)

Три способа внедрения:
1. подменить `Function Library` на свою прокси-DLL;
2. выбрать в OEM-ПО устройство-«shim» (как Fulcrum);
3. включить shim-библиотеку в само приложение (как joeyoravec).

Готовый каркас: `deep-log-capture/scripts/j2534_proxy/` (C + `.def` + build.bat) — логирует все `PassThru*` вызовы и дампы `PASSTHRU_MSG`, форвардит остальное на реальную DLL.

Открытые проекты для вдохновения:
- **MEAT-Inc/Fulcrum** — shim + импорт/конвертация/воспроизведение логов (`.shimLog`), выбор реального устройства попапом.
- **joeyoravec/j2534-logger** — `ptshim32.dll`, экспорт всех PassThru-функций + своих (`PassThruLoadLibrary`/`PassThruSaveLog`…), кольцевой буфер, UTF-8.
- **diamondman/J2534-PassThru-Logger** — логирующий драйвер + UI.
- **kinetekautomotive/etc** — драйвер + over-IP + logger/emulator.
- Python-обвязки (офлайн-разбор и скрипты): keenanlaws/python-j2534-interface (32-битный Python), shamtam/PyJ2534; **emdzej/j2534** (TypeScript; примеры `canlogger`/`klogger` для Tactrix OpenPort 2.0 — тот же FTDI).

## 4. Связка с EDIABAS

BMW-мир поверх J2534 ходит через «OpenPort/OBD32»-совместимые адаптеры (Tactrix OpenPort 2.0 — FTDI внутри) и описан в emdzej/ediabasx-docs (OBD32-протоколы). Для реверса WinKFP: снимай ifh.trc (EDIABAS) + J2534-прокси одновременно — уровни дополняют друг друга.

## 5. Что документировать в своём логе

Для каждой сессии — `PassThruReadVersion` (Api/Dll/Firmware), `SET_CONFIG` параметры (особенно FIVE_BAUD_MOD, PARITY, тайминги), фильтры и периодические сообщения (их отсутствие в логе — частая причина «непонятно, откуда кадры»), `RxStatus/TxFlags` каждого сообщения.
