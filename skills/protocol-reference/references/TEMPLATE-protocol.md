# Спецификация протокола: <НАЗВАНИЕ> («<кодовое имя / как зовут в сканерах>»)

> Шаблон. Заполняй по фактам; каждое утверждение помечай: **wire-verified** (подтверждено логом с живого ЭБУ) / **code-grounded** (из кода/трасс ПО) / **hypothesis** / **не подтверждено**. Удаляй разделы, которых нет, но не удаляй статусы.

- Дата: YYYY-MM-DD · Автор/сессия: …
- Источники: файлы трасс, версии ПО, серийники адаптеров, логи.

## 1. Контекст применения

Модели ЭБУ/машины, годы, софт (INPA/WinKFP/дилерский), где используется: диагностика / программирование / оба.

## 2. Физический уровень

- Линии: K/L/CAN/ENET; пины разъёма; трансивер адаптера.
- Скорость, формат (bits/parity/stop), уровни, подтяжки, инверсии.
- Инициализация линии (питание, wake-up).

## 3. Инициализация соединения

- Метод: 5-baud / fast / без инициации; последовательность байт и тайминги (W1..W5 / TiniL / TWuP / TIdle).
- Key-байты / handshake / авторизация канала.
- Эталонный обмен (лог, байт-в-байт).

## 4. Формат кадра

- Поля и их размеры; **как определяется длина** (в кадре / по сервису / по паузе).
- Чексумма/CRC: точный алгоритм, полином, init, отражение, **что входит в расчёт**; эталонные примеры с посчитанным значением.
- Максимальные размеры, паддинг.

## 5. Адресация

Таблица адресов (тестер, ЭБУ, функциональные/физические), правила ответа.

## 7. Тайминги

- Ответные таймауты, межбайтовые паузы, «мёртвые окна» (операции без ответа), интервалы поллинга.
- Метод измерения (важно: FTDI-лог даёт мс-точность; для мкс — анализатор).

## 8. Сессионная машина

Состояния: idle → соединение → сессии (какие бывают, чем отличаются) → программирование → коммит/сброс. Переходы, признаки отказа, **состояния восстановления** (pending и как выходить).

## 9. Безопасность / доступ

Авторизации (последовательности, seed/key), условия активации, ограничения (что блокируется без авторизации).

## 10. Программирование (если применимо)

Полный сценарий: erase → write → finalize → commit, с эталоном сессии (пошагово, с номерами кадров), размеры блоков, идемпотентность, контроль целостности (CRC регионов, контрольные слова), что одноразово (питание/сессии).

- Что НЕ подтверждено и как проверить.
- Известные дефекты/странности (двузначные команды, зависящие от контекста).

## 12. Приложение: эталонные трассы

Пути к файлам, их назначение; тестовые векторы для юнит-тестов (запрос → ожидаемый ответ → ожидаемая чексумма).
