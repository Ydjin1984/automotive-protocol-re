# Канон формата лога обмена с ЭБУ

Цель формата: лог, снятый ЛЮБЫМ инструментом (наш логгер, Frida, прокси, EDIABAS), должен механически разбираться одним парсером `log-analysis/scripts/telegram_parse.py` и быть пригодным для доказательства в отчёте.

## 1. Обязательные свойства

1. **Шапка** — конфигурация сессии (парсер по шапке восстанавливает контекст: скорость, чётность, протокол).
2. **Монотонные таймстемпы** (миллисекунды, желательно микросекунды) + **якорь wall-clock** в шапке. Внутри — только монотонное время, никаких `DateTime.Now` на каждую строку.
3. **Направление** на каждой записи: `TX` (мы передали), `RX` (получено), `ECHO` (получено, но равно нашему TX), `EH` (эхо от адаптера), служебные `..`/`!!`.
4. **Сырые байты** в hex, заглавными, через пробел. Никакой интерпретации (декод — отдельным проходом).
5. **Ошибки видны**: обрывы, таймауты, `<read-error …>`, кадровые ошибки.

## 2. Текстовый формат (канон)

```
# automotive-protocol-re log v1
# time=2026-10-12 09:53:16            (wall-clock якорь)
# adapter=FT232R sn=A1B2C3D4 drv=D2XX 3.2.4.0
# port=USB idx=0 baud=9600 data=8 parity=E stop=1 latency_ms=1
# protocol=DS2 target=0x12 ecu_sw=1430940 tool=HwProbe/1.0 user=lex
[+0.000s] OPEN ok
[+0.104s] TX 12 04 00 16
[+0.241s] RX 12 2e A0 31 34 33 30 39 34 30 ... 9F
[+0.243s] EH 12 04 00 16   ; echo of TX
[+1.502s] !! no response within 1200 ms (attempt 1/4)
# session end: tx=1 rx=1 echo=1 errors=1 duration=2.104s
```

Грамматика строки:

```
[+<sec>.<ms>s] <DIR> <HEX BYTES> [ ; <комментарий>]
DIR ∈ {TX, RX, EH, OPEN, CLOSE, .., !!}
```

Реальные совместимые «диалекты» (парсер обязан понимать все):

| Источник | Пример строки | Регексп |
|---|---|---|
| Наш логгер / HwProbe | `[16:39:35.698] TX 12 04 00 16` | `^\[(\d+):(\d+):(\d+\.\d+)\]\s+(TX|RX)\s+([0-9A-F ]+)$` |
| HwProbe (эхо/аккумуляция) | `[07:56:01.909] RX 12 04 0D 1B   <= echo of TX` | `<= echo of TX` |
| Frida-логгер | `[+94.086s] TX ftd2xx FT_Write rc=0 len=4 n=4 : 12 04 00 16` | `^\[\+([\d.]+)s\]\s+(TX|RX)\s+(\S+)\s+(\S+)\s+(.*?)\s*:\s*([0-9a-f ]+)$` |
| Frida-логгер (VCP) | `[+70.537s] VCP TX WriteFile(COM6) n=4 : 12 04 0d 1b` | то же |
| EDIABAS ifh.trc | `_STD      INPUT: 12 04 00` / `_STD      OUTPUT: 12 2E A0 …` | `^\S+\s+(INPUT|OUTPUT):\s+([0-9A-F ]+)$` |

## 3. JSONL-дубль (машинный формат)

Первая строка — метаданные, далее по объекту на запись:

```json
{"kind":"meta","time":"2026-10-12T09:53:16+03:00","adapter":"FT232R","serial":"A1B2C3D4","driver":"D2XX 3.2.4.0","baud":9600,"parity":"E","data_bits":8,"stop_bits":1,"latency_ms":1,"protocol":"DS2","target":18,"tool":"ftdi_kline_logger/1.0"}
{"kind":"open","t":0.0}
{"kind":"data","t":0.104,"dir":"tx","src":"ftd2xx","bytes":"12 04 00 16","note":""}
{"kind":"data","t":0.241,"dir":"rx","src":"ftd2xx","bytes":"12 2e A0 31 …","note":"ident"}
{"kind":"error","t":1.502,"text":"no response within 1200 ms","attempt":1}
{"kind":"meta_end","tx":1,"rx":1,"echo":1,"errors":1,"duration":2.104}
```

Правила: `t` — секунды от старта с 3 знаками; `bytes` — заглавный hex через пробел; `note` — свободный текст; неизвестные поля парсер обязан игнорировать (совместимость вперёд).

## 4. Что писать в шапку обязательно

- **Адаптер**: чип (FT232R/FT2232H/…), серийник, драйвер и его версия (D2XX `FT_GetLibraryVersion` / VCP-порт).
- **Параметры линии**: baud, bits/parity/stop, latency, таймауты. Для K-line — кто инвертирует (трансивер? дискретка?).
- **Целевой ЭБУ**: адрес(а), софт-версия (если известна), VIN.
- **Инструмент**: имя и версия (наш скрипт или перехватываемая программа + версия).
- **Что делаем**: сценарий сессии одной фразой (ident / read / write cal / flash / listen).

## 5. Анти-паттерны

- Логировать «уже разобранные» телеграммы без сырых байт — ломает перепроверку.
- Таймстемпы только wall-clock без монотонного времени — прыжки при синхронизации NTP.
- Смешивать несколько сессий в один файл без разделителей — парсеры путают состояния.
- Писать лог в синхронизируемую папку (OneDrive) во время долгого флеша — блокировки файла.
- Терять эхоотметки: без них невозможно посчитать реальные задержки ответа (и отличить молчание ЭБУ от эха адаптера).
