# j2534_proxy — логирующая прокси для SAE J2534 Pass-Thru

Перехватывает ВСЕ вызовы J2534 API между диагностическим ПО (ODIS, Techstream, флешеры, GDS2 и т.п.) и адаптером (OpenPort 2.0, RLink 2534, VCM II, MVCI, самодельные). В логе — вызовы, протоколы, скорости, дампы `PASSTHRU_MSG` с микросекундными таймстампами адаптера.

## Схема

```
Диагностическое ПО (32-бит)  →  J2534.dll (НАША прокси)
                                   ├─ PassThru* → лог + вызов реальной DLL
                                   └─ реальная DLL: J2534_REAL_DLL / j2534_proxy.ini / реестр
```

## Установка

1. Собрать (x86!): `build.bat` из «x86 Native Tools Command Prompt».
2. Найти реальную DLL: реестр `HKLM\SOFTWARE\WOW6432Node\PassThruSupport.04.04\<Vendor>` → `Function Library`. Скопировать оригинал в отдельное место (например `C:\j2534real\vendor.dll`).
3. Внедрение — один из способов:
   - **проще**: положить прокси рядом с EXE программы под **тем именем**, под которым ПО грузит DLL (часто совпадает с именем vendor-DLL, напр. `op20pt32.dll`);
   - **надёжнее**: подменить значение `Function Library` в реестре на путь к прокси (сохрани исходное значение!);
   - либо выбрать устройство-«shim», если ПО это умеет (как Fulcrum).
4. Создать `j2534_proxy.ini` рядом с прокси: `RealDll=C:\j2534real\vendor.dll` (или задать `J2534_REAL_DLL`).
5. Отработать сценарий → `j2534-log-*.log` рядом с EXE.

## Что видно в логе

- `PassThruConnect proto=ISO14230(4) flags=0x0 baud=10400` — какой протокол/скорость/флаги выбрало ПО;
- `J2534 TX/RX ... len=5 : 81 10 F1 81 03` — дампы кадров с `TxFlags`/`RxStatus`/`Timestamp`;
- `PassThruIoctl id=4 (FIVE_BAUD_INIT)` — аппаратная инициализация (какие key-байты);
- периодические сообщения, фильтры, `SetProgrammingVoltage` (pin/voltage!), версии API/DLL/FW, тексты ошибок.

## Чек-лист «не работает»

- [ ] Прокси 32-битная? (J2534-ПО практически всегда x86.)
- [ ] В логе есть `# j2534_proxy attached`? Если нет — ПО загрузило не нашу DLL (search order/имя).
- [ ] Реальная DLL найдена (`# original J2534 loaded: ...`)? Проверь ini/переменную/реестр.
- [ ] ПО требует **наш** SerialNumber/Config App из реестра → продублируй в свой ключ (Fulcrum так и делает).
- [ ] Антивирус/подпись: неподписанная DLL в чужой папке может блокироваться.
